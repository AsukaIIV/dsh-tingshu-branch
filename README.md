# 听书稿分支（dsh-tingshu-branch）

把任意一段 DSH 对话变成一份**口语化、适合听的 txt 稿件**：不复制对话原文，而是把一份固定的写作命令投给一个继承上下文的分支会话，由它读完上下文后自己写。

插件本身不写稿子，只做确定性的事：

1. 算好文件名——`听书稿_<主题>_<YYYYMMDD>_v<N>.txt`，日期取当天（默认 `Asia/Shanghai`），`N` 是当天的第几版（扫目录自动 +1，永不覆盖旧稿）；
2. **问一下模型自己还剩多少地方**，再决定怎么投递（见下节）；
3. 用 `sessionController.prompt` 把命令全文（含确定的绝对路径、主题、篇幅、写作硬约束）投给目标会话，让它自己开写。

## 投递方式由模型的上下文预算决定

分支会整段继承源会话的上下文，所以「该不该 fork」的答案是模型自己的窗口说了算，不是某个写死的字数。插件读两个真数据：

| 数 | 从哪来 |
|---|---|
| 这次请求要装多少 token | `ctx.tokenMeter.measure(session).totalTokens` |
| 这个模型窗口多大 | `session.requestContext().contextWindow` |

判定规则：

- 占用 ≤ 窗口的 **50%** → 派生分支（`sessionController.fork`），让分支带着上下文直接写；
- 占用 > 50% → 改走**素材分块 + 新会话**：把对话正文抽成纯文本、按窗口大小切块落到磁盘，再 `sessionController.create()` 开一个全新空会话，让它「读一块、写一节」，最后按序拼接；
- 两个数有一个读不到（比如换了自定义 provider 没报窗口）→ 退回字数兜底（默认 45000 字），并在返回里明说「读不到模型窗口，按字数判」。

比例是配置项 `forkWindowRatio`，默认 0.5。之所以留一半：光继承下来还不够，写稿过程中还要读文件、写几万字、跑工具，那部分也得占地方。

分块时的块大小也跟着窗口走：一块不超过窗口的 5%（下限 1500 字，默认 6000 字）。

素材从 `sessionQuery.readSurface()` 取——那是**模型当前真正看到的表面**（压缩之后的），不是原始日志。只保留人和模型的正文，`system-reminder`、`<acp>` 标签、时间采样行、运行时房务行、工具调用与工具返回全部丢掉；长对话里最占地方的恰恰是这些。

分块模式下会多一个素材目录：`<会话目录>\听书稿素材_<YYYYMMDD>_<会话号后八位>\`，里面 `01.txt …NN.txt` 是素材块，`节01.txt …` 是分支写出的分节，最后按编号拼成 `听书稿_…_vN.txt`。中间产物保留，不自动删。

素材超过 60 块时会自动加粗每块，不会让分支跑上百轮。

## 怎么用

在输入框里敲命令：

```
/tingshu                                  # 主题取当前目录名，默认约 75 分钟
/tingshu -t 光纤光栅复刻 -m 40             # 指定主题与目标时长
/tingshu 少讲背景，重点讲返工那几段         # 自由文本＝本次额外要求，原样带给分支
/tingshu -t 温度解调 -m 90 面向完全外行     # 参数与自由文本可以一起给
```

模型侧也有同名能力的工具 `tingshu_branch`（参数 `topic` / `minutes` / `extra`），用户说「把这次对话做成听书稿」时它会被选中。两者走同一个 `launch()`，不存在两套实现。

工具/命令的返回里会带上这次用了哪条路、以及依据（窗口多少 token、已占多少、占了几成），不用去翻日志。

命令返回后，目标会话是**独立会话**，在会话列表里能看到它自己跑完并回一份自检报告（行数、字数、章节清单、阿拉伯数字计数、英文缩写计数、是否出现列表表格）。

## 命令全文里钉死了什么

- 输出路径原样使用，不许改名、改日期、改版本号、另建目录；
- 篇幅按「每分钟约 260 字」换算，允许上下两成；
- 事实只用素材里真的发生过的，且要先读对话里点到的报告/规格文件；严禁编造数字与实验；
- 保留弯路与失败，因为那是这类稿子最值钱的部分；
- 硬约束：零阿拉伯数字、零英文缩写、不用列表/表格/代码块/反引号、每段空行做停顿、不写「如上表所示」；
- 分块模式额外钉死流程：先读一块再写一节，**同一时刻手里只拿一块**，不许一次读两块、不许先全读完；最后用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))` 拼接成无 BOM 的 UTF-8，再只做局部顺稿；
- 交稿时逐项自检并报告。

## 配置

`cordis.patch.yml`：

```yaml
- insert:
    - id: tingshu-branch
      name: dsh-tingshu-branch
      config:
        minutes: 75            # 默认目标时长
        timeZone: Asia/Shanghai
        forkWindowRatio: 0.5   # 窗口用到几成就改走分块
        forkLimit: 0           # 0＝完全按预算自动决定；正数＝再加一道字数硬闸
        charFallback: 45000    # 读不到模型窗口时的字数兜底
        chunkChars: 6000       # 分块模式每块的字数上限（会被窗口 5% 压低）
```

## 安装 / 改动

```powershell
# 安装：plugin_manager install_bundle → C:\Users\User\.dsh\plugins\dsh-tingshu-branch
# 或者从 GitHub 拿：
git clone https://github.com/AsukaIIV/dsh-tingshu-branch.git
```

安装是 **link**，改这里源文件即刻影响已安装的包；但 Host 侧 ESM 模块世代不会热替换，改了 JS 之后要重装或重启 DSH 才生效（或者 `set_bundle` 先禁用再启用）。

## 为什么要走「分支 + 命令」而不是在插件里写稿

上一版（`dsh-tingshu`，2026-11）试图在 Host 里直接读会话日志、拼稿、推 Git，撞了三类坑：bundle 挂载缺少 `dsh.bundle.patch` 导致行不生效、slot 组件的 `sessionId` 要靠 `inject` 传入导致按钮点了没反应、`sessionPersistence` 服务在 `apply()` 阶段还没创建导致接口五百。分支方案把这些全绕开了：分支自带上下文，写入交给一个会读文件、会自检的 agent，插件只负责确定性部分。

## 已知边界

- 走分支时源会话必须至少有一轮已完成对话，否则 `fork` 会拒绝（返回「没有可 fork 的轮次」）。
- 走分块时新会话**没有任何继承上下文**，全部信息来自素材块；素材抽不干净（比如关键结论只在工具输出里）就会漏。
- 写作是异步的，插件不等待、也不代写；稿件质量取决于目标会话读完素材后的判断。
- 主题只影响文件名，不影响内容。

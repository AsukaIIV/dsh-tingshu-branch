# 听书稿分支（dsh-tingshu-branch）

把任意一段 DSH 对话变成一份**口语化、适合听的 txt 稿件**：不复制对话原文，而是分出一个继承了上下文的**分支会话**，把一份固定的写作命令投给它，由它读完上下文后自己写。

插件本身不写稿子，只做三件确定性的事：

1. 算好文件名——`听书稿_<主题>_<YYYYMMDD>_v<N>.txt`，日期取当天（默认 `Asia/Shanghai`），`N` 是当天的第几版（扫目录自动 +1，永不覆盖旧稿）；
2. 用 `sessionController.fork` 从当前会话分出一个分支（继承已完成轮次的上下文，不需要手工搬运或解码会话日志）；
3. 用 `sessionController.prompt` 把命令全文（含确定的绝对路径、主题、篇幅、写作硬约束）投给分支，让它自己开写。

## 怎么用

在输入框里敲命令：

```
/tingshu                                  # 主题取当前目录名，默认约 75 分钟
/tingshu -t 光纤光栅复刻 -m 40             # 指定主题与目标时长
/tingshu 少讲背景，重点讲返工那几段         # 自由文本＝本次额外要求，原样带给分支
/tingshu -t 温度解调 -m 90 面向完全外行     # 参数与自由文本可以一起给
```

模型侧也有同名能力的工具 `tingshu_branch`（参数 `topic` / `minutes` / `extra`），用户说「把这次对话做成听书稿」时它会被选中。两者走同一个 `launch()`，不存在两套实现。

命令返回后，分支是**独立会话**，在会话列表里能看到它自己跑完并回一份自检报告（行数、字数、章节清单、阿拉伯数字计数、英文缩写计数、是否出现列表表格）。

## 命令全文里钉死了什么

- 输出路径原样使用，不许改名、改日期、改版本号、另建目录；
- 篇幅按「每分钟约 260 字」换算，允许上下两成；
- 事实只用对话里真的发生过的，且要先读对话里点到的报告/规格文件；严禁编造数字与实验；
- 保留弯路与失败，因为那是这类稿子最值钱的部分；
- 硬约束：零阿拉伯数字、零英文缩写、不用列表/表格/代码块/反引号、每段空行做停顿、不写「如上表所示」；
- 交稿时逐项自检并报告。

## 配置

`cordis.patch.yml` 里两行：

```yaml
- insert:
    - id: tingshu-branch
      name: dsh-tingshu-branch
      config:
        minutes: 75
        timeZone: Asia/Shanghai
```

## 安装 / 改动

```powershell
# 安装（首次）
plugin_manager install_bundle → C:\Users\User\.dsh\plugins\dsh-tingshu-branch
```

安装是 **pnpm link**，改这里源文件即刻影响已安装的包；但 Host 侧 ESM 模块世代不会热替换，改了 JS 之后要重装或重启 DSH 才生效。

## 为什么要走「分支 + 命令」而不是在插件里写稿

上一版（`dsh-tingshu`，2026-11）试图在 Host 里直接读会话日志、拼稿、推 Git，撞了三类坑：bundle 挂载缺少 `dsh.bundle.patch` 导致行不生效、slot 组件的 `sessionId` 要靠 `inject` 传入导致按钮点了没反应、`sessionPersistence` 服务在 `apply()` 阶段还没创建导致接口五百。分支方案把这些全绕开了：分支自带上下文，写入交给一个会读文件、会自检的 agent，插件只负责确定性部分。

## 已知边界

- 会话必须至少有一轮已完成的对话，否则 `fork` 会拒绝（返回「没有可 fork 的轮次」）。
- 分支写作是异步的，插件不等待、也不代写；稿件质量取决于分支读完上下文后的判断。
- 主题只影响文件名，不影响内容。
